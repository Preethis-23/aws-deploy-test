Deployment Architecture Flow

Deploying an interactive site from your local machine to AWS EC2 via modern CI/CD requires automation. Here is how your code flows from your editor to the live web server on EC2.

💻
Developer Commit
🐙
GitHub Repo
⚙️
CI/CD Runner
☁️
AWS EC2 Server
🚀
Live Web App

Why GitHub Actions is best for this setup:

Advantages

  • Fully Hosted: No need to run or manage a dedicated build server.
  • Secure Secrets: Built-in encrypted secrets for storing EC2 SSH keys.
  • GitHub Native: Triggers automatically on git events (push, PR).
  • Free Tier: Extremely generous free minutes for public & private repos.

What it requires from you

  • A GitHub repository containing your site files.
  • A configuration YAML file stored in .github/workflows/deploy.yml.
  • Configured Repository Secrets (Host IP, SSH Private Key, Username).

Why use Jenkins (Genkins):

Advantages

  • Self-Hosted Control: Complete control over the build environment.
  • Extensible: Thousands of plugins available for almost any integration.
  • On-Premise: Perfect for closed security networks/enterprise environments.

What it requires from you

  • A dedicated server (like a separate EC2) running Jenkins 24/7.
  • Installing Java, Jenkins packages, and dependencies on the server.
  • Setting up credentials and configuring a webhook in your GitHub Repo.

Launch AWS EC2 Instance

Log into your AWS Management Console and follow these steps to provision your deployment server:

  • Open the EC2 Dashboard and click Launch Instance.
  • OS: Select Ubuntu Server 22.04 LTS (Free Tier eligible).
  • Instance Type: Choose t2.micro (or t3.micro).
  • Key Pair: Generate a new key pair, choose RSA and .pem format. Download and store this file safely (e.g., aws-key.pem).
  • Network Settings: Create a new Security Group:
    • Allow SSH (Port 22) from your IP.
    • Allow HTTP (Port 80) from Anywhere (0.0.0.0/0) to serve the site.
Pro Tip: Copy the Public IPv4 Address of your launched instance. You'll need it for the configurations and pipeline.

Configure EC2 Web Server

Connect to your newly launched EC2 instance using SSH to install a web server (Nginx) to host the static files. Run these commands in your local shell terminal:

SSH Terminal
# 1. Update permissions on your downloaded private key
chmod 400 path/to/aws-key.pem
# 2. Connect to the EC2 Instance
ssh -i path/to/aws-key.pem ubuntu@<YOUR_EC2_PUBLIC_IP>
# 3. Update packages and install Nginx web server
sudo apt update && sudo apt install nginx -y
# 4. Change web root ownership so the build runner can upload files without root
sudo chown -R ubuntu:ubuntu /var/www/html

Once completed, navigating to your http://<EC2_PUBLIC_IP> in a browser should display the default Nginx Welcome Page. This indicates the server is ready!

Configure GitHub Actions Secrets

GitHub Actions runs on secure, remote runners. To safely upload files to your EC2 instance, you must supply your SSH keys as Encrypted Repository Secrets:

  • Go to your GitHub Repository -> Settings tab.
  • On the left sidebar, expand Secrets and variables -> select Actions.
  • Click New repository secret and add the following:
EC2_HOST
Your AWS EC2 Public IPv4 IP Address.
EC2_USERNAME
The default SSH username (e.g. ubuntu for Ubuntu OS, or ec2-user).
EC2_SSH_KEY
The full content of your private key file (.pem file content including headers).
Important Security: Never commit your raw private PEM key or server IPs directly into the code repository. Always use GitHub Secrets!
